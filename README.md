1. Business Scenario
Sunrise Supermarket sells various products for customers. Customers place orders for products, and an order can include several products.
Management wants to determine the purchasing behavior of customers, what products are bought, and sales trends. Several SQL queries were executed to obtain, organize, and analyze the supermarket's data.
2.Project Summary
The project involved developing a conceptual database for the Sunrise Supermarket.
The database involved the following tables:
Customers – customer details.
Products – product names, categories, and prices.
Orders – customer orders and dates.
Order Items – products ordered and their quantities.
The database was populated with the following data:

30 order items

4.SQL Queries and Explanations
4.1 JOIN query 1 – Orders with Customer information
This query involves an INNER JOIN of the orders and customers tables.
The query will display the following information:
Order ID
Customer name
Customer city
Order date
This query will connect orders with customer details.
Business Interpretation
The INNER JOIN helps the Sunrise Supermarket management understand who placed the orders, where the customers are, and the order dates.
4.2 JOIN query 2 – Order Items with Product Information
This query involves INNER JOIN of the order_items and products tables.
The query will display the following information:
Order item ID
Product name 
Product category
Product price
Quantity
The query will connect order items and product details.
 Business Interpretation
This query will help the supermarket management determine the products in each order and their quantities.
4.3 JOIN query 3 – Customers and Their Orders
This query involves a LEFT JOIN  of the customers and orders tables.
The query will display the following information:
Customer ID 
Customer name
City
Order ID
Order date
This query will connect customer detail with customer orders.
 Business Interpretation
The LEFT JOIN ensures that all customers are displayed despite having no orders.
This query helps the management know which customers have no orders.
5. CTE query – Customers Above Average spending
The CTE query below helps get customers who spend more than the average amount.
CTE calculates the total amount spent by every by multiplying the quantity by the product price.
The query then compares the average amount spent by all customer and displays those who spend more than the average.
Business Interpretation
The CTE query helps the management determine which customers are willing to spend more and target them.
6. Window Functions
 6.1 Window Query 1 — Rank Customers by Spending
This window function ranks customers according to their total spending from highest to lowest.
The RANK () window function determines the rank of each customer based on their spending.
Business Interpretation
This ranking helps the management know which customers are spending the most.

6.2 Window Query 2 — Number of Orders per Customer
This window function numbers the orders placed by each customer according to the order date.
The ROW_NUMBER () function numbers the orders for each customer.
Business Interpretation
This helps the management know how many times each customer has placed an order.

 6.3 Window Query 3 — Running Total of Revenue
This query involves calculating the running total of revenue.
This query uses a CTE to determine each order's revenue and then uses the SUM () window function to calculate the total revenue.
 Business Interpretation
This query helps the management know the total revenue generated by processing all the orders.
6.4 Window Query 4 — Days Between Orders
This query involves determining the number of days between one order and the next using the LAG () window function.
The query also determines the number of days between the current order and the one immediately preceding it using the DATEDIFF () function.
The query only displays customers with more than one order.
 Business Interpretation
This query helps the management know how long it takes, on average, for a customer to reorder.

Solution: Convert Oracle SQL data types to their MySQL equivalents.

The tables had to be related to each other so that orders belong to customers and order items belong to orders and products.
